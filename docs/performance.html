Docs · Performance

Measured, not guessed.

Numbers from the live integration queue, and the honest cost model behind them.

Integration Queue timings

ScenarioWall timePer item
3 clean PRs (churn)18–22 s~6–7 s
10 clean PRs~42 s full queue→done~4.2 s

Each integration does a scratch clone for preview plus a scratch clone + push for the merge — repeated full object transfer. At this scale it is acceptable; the data justifies a cached bare-mirror + shared-object worktree model as the next optimization target.

What dominates

  • Clone preparation (full object transfer per operation).
  • Preview + merge each clone once.
  • Strict FIFO serializes integrations (by design).

What is not yet measured

  • Concurrent agent execution at scale (the deterministic adapter is subprocess-fast; real LLM executors are bounded on the credential condition).
  • Repository-size effects (all tests used small repos).
  • SSE fan-out under many browsers (single-node).
