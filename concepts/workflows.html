Concepts · Durable workflows

JS you can crash on.

Workflows are authored in JavaScript, but their state is not the lifetime of a process. Durable steps, replay, and bounded autonomy.

The authoring model

A workflow is a function run(ctx) that calls Switchyard operations. Ordinary local computation between the calls runs normally; only the operations are durable boundaries. 

function run(ctx) {
  await ctx.agent({ repo, branch, file, append });
  await ctx.check({ repo, branch });
  await ctx.review({ repo, branch });
  await ctx.parallel([
    () => ctx.agent({ ... }),
    () => ctx.review({ ... }),
  ]);
  await ctx.wait_approval({ reason });
  await ctx.integrate({ repo, branch, base });
}

Durability by replay

  • Every operation is a durable step keyed by (run_id, step_key, args_hash).
  • On restart the script re-runs from the top; completed steps replay their recorded result.
  • In-flight steps retry (at-least-once); later steps run exactly once.
  • External effects are never duplicated.

This is proven by killing the control plane during a running durable step: the completed agent step replayed with attempts=1, the in-flight sleep retried, later steps ran once, and the execution count was exactly right.

Governance

  • Step budgets and bounded recursion are enforced.
  • Workflows can spawn children and wait on human approval.
  • Determinism is enforced: no wall-clock in control flow, seeded ctx.random(seed).
