Product · Overview

One loop for humans and agents.

Switchyard turns a normal Git repository into a place where concurrent agents and people can work without stepping on each other — and where every canonical change is explainable.

The core model

  1. Work — an intent is recorded (feature, fix, task).
  2. Attempt — an isolated branch is created from the intent.
  3. Agent or human — edits files on that branch.
  4. Commit — lands via a compare-and-swap ref substrate on the attempt branch only.
  5. PR + check + review — a pull request, validation, and structured findings.
  6. Preview — does it merge cleanly, and does the merged tree satisfy the repo contract?
  7. Integration Queue — strictly FIFO, policy-gated, CAS-guarded into canonical.

Nothing on canonical happens outside that pipeline. Agents are incapable of writing canonical by themselves, because they never hold a credential for it.

Why isolation is the point

Concurrency

Parallel, safe

Two agents editing the same file produce a conflict the repair loop handles — they never clobber each other on canonical.

Attribution

Provenance

Work → Attempt → PR → ref updates → events: a full, queryable chain for every canonical change.

Control

Policy

Which files agents may write, which integrations need approval, how much a workflow may run — all audited.

Deterministic by default

The loop is fully deterministic today: the implementer, checker, reviewer and conflict-resolver are deterministic adapters behind one runner interface. A real coding-agent CLI adapter is wired and ready; it is the same substrate, with a provider credential as the only missing input. This is what lets the system be certified, isolated, and debuggable before LLM variance is introduced.
