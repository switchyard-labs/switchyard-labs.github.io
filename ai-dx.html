AI developer experience

Give agents a real engineering substrate — not a sandbox that has nothing to do with your repository. Roles, scoped credentials, durable workflows, and a canonical branch agents cannot reach.

Agent model

  • Roles (implementer / reviewer / conflict-resolver) with explicit capabilities. A provider secret never grants Switchyard authority; capabilities are role-scoped.
  • Scoped execution: agents hold repo tokens for their attempt branch only. Canonical-write credentials are never given to an agent.
  • Pluggable runner: one interface, two adapters — a deterministic worker (proven, used for certification and isolation) and a coding-agent CLI adapter (wired, pending a provider credential).

Credentials

  • Encrypted at rest (AES-256-GCM); the secret is never returned by any endpoint.
  • Create / list-metadata / rotate / delete lifecycle with zero plaintext exposure.
  • Plaintext materializes only during execution resolution (scoped 0600 file).
  • Threat model documented honestly: a co-located key protects against database-only compromise, not full host compromise. KMS/external secret backends are CP14+/hosted options.

Durable programmable workflows

function run(ctx) {
  await ctx.agent({repo, branch, file, append});
  await ctx.check({repo, branch});
  await ctx.review({repo, branch});
  await ctx.parallel([
    () => ctx.agent({...}),
    () => ctx.review({...}),
  ]);
  await ctx.wait_approval({reason});
  await ctx.integrate({repo, branch, base});
}
  • Durable boundaries are explicit Switchyard operations; ordinary local JS computation between them runs normally.
  • Crash/restart is safe: completed steps replay, in-flight steps retry, nothing external is duplicated.
  • Budget (step cap) and bounded recursion are enforced; workflows can spawn children and wait on human approval.

Determinism

Workflow scripts are replayed from the top, so they must be deterministic: wall-clock and entropy are removed from the interpreter surface (Date.now → 0, seeded ctx.random(seed)). The step-key counter is deterministic per pass, so replay converges to the same durable steps.

Execution records & provenance

Every agent run is an execution record: role, adapter, status, output, started/finished. Every canonical change carries provenance (workflow / attempt / queue / decision). A change's full chain is queryable.

Concurrency, not last-writer-wins

  • Ref mutations are compare-and-swap; a stale agent commit is rejected by Git itself.
  • Draft saves use revision CAS: an agent result based on an older draft revision is rejected rather than overwriting the human's newer edit (proven: Race B in the draft concurrency gate).
  • Two agents editing the same file produce a preview conflict that routes to the repair loop — they never clobber each other on canonical.

Autonomy + policy

  • Org policies gate agent writes (deny_paths), workflow budgets, and integration risk.
  • High-risk integrations require approval (escalated, then decided by a human through a decision packet).
  • The audit trail records every policy decision.
