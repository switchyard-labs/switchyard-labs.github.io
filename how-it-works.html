The engineering loop, in detail

What actually happens from "an intent exists" to "canonical moved" — and the evidence that each step is real, not a diagram.

The loop

  1. Work is created (title, kind, owner).
  2. Attempt is opened on an isolated branch (e.g. attempt-<id>) with a marker file.
  3. Agent (implementer role) reads the branch, edits a bounded file, and commits via the ref substrate. Every run is an execution record (role, adapter, status, output).
  4. Check validates the marker (deterministic; real CI-style hooks are future work).
  5. PR is opened from the attempt branch against base.
  6. Review produces structured findings (severity, message, file).
  7. Preview integration: does the branch merge into current canonical cleanly? If yes, is the merged tree semantically valid (repo contract)?
  8. Integration Queue integrates the PR into canonical only when policy allows, strictly FIFO, CAS-guarded.
  9. Provenance records the whole chain.

Evidence behind each step

CapabilityLive proof
Real Git hostingOrdinary git clone/push against Cloudflare Artifacts; refs and objects are exactly what git wrote.
Ref CASThree concurrent writers to one ref → exactly one success, clean stale handling (CP3/CP4).
Durable workflowsControl plane killed during a running durable step; on restart the completed agent step replayed, not re-executed (attempts=1), the in-flight sleep retried, later steps ran once, no duplicated external effects (CP7).
Textual conflict handlingTwo attempts editing the same line: preview finds the Git conflict, the conflict-resolver performs a three-way merge, re-preview is clean, integration succeeds (CP8).
Semantic conflictAttempt A bumps api.version and the consumer together (contract holds). Attempt B adds a new consumer requiring an incompatible version — git merge is clean, but contract validation on the merged tree reports the mismatch, parks the attempt, and blocks the queue (post-CP13 experiment, 5/5).
Integration queue under churnStrict FIFO: 3 clean PRs integrate in order; same-file contention blocks the second and repairs via requeue; measured ~18–22 s for 3 PRs and ~42 s for 10 PRs (CP9).
Editor concurrencyDraft revision CAS: two sessions both load rev 1; the second save is rejected (draft_stale), and an external push between draft and commit is detected (stale_base). No last-writer-wins (post-CP13, 6/6).
DogfoodingSwitchyard ran its own source through the full deterministic loop and integrated the result into canonical (CP13, 7/7).

Realtime

The control plane is the coordination truth, so it is also the realtime source: authenticated SSE (/api/events/stream) delivers normalized domain events to browsers. Reconciliation catches external git pushes and they appear live without a refresh. A distributed Worker/DO fan-out remains a later hosted-scale option.
