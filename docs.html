Setup & running Switchyard

Everything you need to stand up the control plane, connect it to Cloudflare Artifacts and Trestle, and run the verification gates.

Prerequisites

  • A Cloudflare account on the Workers Paid plan (Artifacts is Paid-only).
  • Artifacts access (an account token / OAuth with artifacts.read and artifacts.write scopes).
  • A token helper — a small script that prints a fresh account token (e.g. the Cloudflare cf CLI OAuth token). The control plane never holds a static credential.
  • A Trestle instance (single-node is enough for v1) with an admin user/password.
  • Go 1.22+ to build the control plane; git on the host; the Strut worker binary for the deterministic adapter.

SWITCHYARD_ARTIFACTS_NAMESPACEArtifacts namespace (default switchyard-cp0).
SWITCHYARD_ARTIFACTS_TOKEN_CMDToken helper path.
SWITCHYARD_STATIC_DIRNift build output directory (the web app).
SWITCHYARD_LISTENListen address (default 127.0.0.1:8080).
SWITCHYARD_DATA_DIRControl-plane data (scratch clones, secret key).
SWITCHYARD_STRUT_BINStrut worker binary (deterministic adapter).
SWITCHYARD_RECONCILE_INTERVALReconciliation period (default 15s).
SWITCHYARD_QUEUE_IDCloudflare Queue id for the event fast path (optional; reconciliation is the safety net).
SWITCHYARD_QUEUE_PULL_INTERVALQueue pull period (default 5s).
SWITCHYARD_WORKFLOW_INTERVALWorkflow runner period (default 2s).
SWITCHYARD_QUEUE_INTEGRATE_INTERVALIntegration queue worker period (default 3s).
SWITCHYARD_SECRET_KEYOptional 32-byte key for credential encryption; otherwise persisted to data/secret.key.

Build & run

# build the control plane
go build -o switchyard ./cmd/switchyard

# run with a start script sourcing the env
cat > cp0.env <<'EOF'
SWITCHYARD_TRESTLE_URL=http://127.0.0.1:7350
SWITCHYARD_TRESTLE_USER=admin
SWITCHYARD_TRESTLE_PASS=CHANGE_ME
SWITCHYARD_ARTIFACTS_ACCOUNT=YOUR_ACCOUNT_ID
SWITCHYARD_ARTIFACTS_NAMESPACE=switchyard-cp0
SWITCHYARD_ARTIFACTS_TOKEN_CMD=/opt/switchyard/token.sh
SWITCHYARD_STATIC_DIR=/opt/switchyard/public
SWITCHYARD_LISTEN=127.0.0.1:8080
SWITCHYARD_DATA_DIR=/opt/switchyard/data
SWITCHYARD_STRUT_BIN=/opt/switchyard/deterministic-worker
SWITCHYARD_RECONCILE_INTERVAL=15s
SWITCHYARD_QUEUE_ID=YOUR_QUEUE_ID        # optional
SWITCHYARD_QUEUE_PULL_INTERVAL=5s
SWITCHYARD_WORKFLOW_INTERVAL=2s
SWITCHYARD_QUEUE_INTEGRATE_INTERVAL=3s
EOF

set -a; source cp0.env; set +a
./switchyard

On startup the control plane provisions its Trestle collections, starts the reconciler, the optional queue consumer, the workflow runner, and the integration queue worker, then serves the app on the listen address.

The web app

  • / — dashboard (repos, work, live activity via SSE).
  • /repos.html?name=…&ref=…&path=… — repository browser.
  • /edit.html?name=…&ref=…&path=…&attempt=… — the CodeMirror editor (Save draft ≠ Commit, diff, findings, Agent panel).
  • /work.html — work items.

Verification gates

The campaign's live gates live in experiments/cpN/ in the repository. They drive the control plane through real repositories: deterministic slices, workflows, review/conflict, the integration queue (including performance), the browser editor (Playwright + Chromium), Needs Attention / escalation, org policy, and dogfooding.

Operations notes

  • Provisioning is idempotent; restart-safe (reconciliation + durable records).
  • Credential backups: the data/secret.key + Trestle records together restore the store.
  • Schema migrations, service lifecycle, and disaster recovery are CP14 items.
