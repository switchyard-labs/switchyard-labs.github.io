How it all fits together

Two truths, one substrate, and a pipeline that turns intent into canonical Git while keeping agents incapable of writing canonical by themselves.

The ref substrate

Every canonical mutation goes through Update(repo, ref, expected, changes, message, provenance):

  1. Read the current SHA (git ls-remote).
  2. Build a commit from the requested file changes.
  3. Push non-force. Git itself rejects stale writers ("fetch first").
  4. On rejection: STALE — reconcile (or re-queue with bounded attempts).
Force-push is policy-gated and never used by the integration path. Agent principals hold no canonical-write credential at all.

Durable workflows

Workflows are authored in JavaScript and executed by a constrained interpreter (goja). The authoring model is a function run(ctx) that calls Switchyard operations: 

function run(ctx) {
  await ctx.agent({repo, branch, file: "ATTEMPT.md", append: "…"});
  await ctx.check({repo, branch});
  await ctx.review({repo, branch});
  await ctx.wait_approval({reason: "merge to main"});
  await ctx.integrate({repo, branch, base: "main"});
}

Durability is replay-from-top: every Switchyard operation is a durable step keyed by (run_id, step_key, args_hash). On executor death / restart the script re-runs; completed steps replay their recorded result instead of re-executing, so external effects are never duplicated. In-flight steps retry (at-least-once). Cancellation, budgets, and bounded recursion are enforced.

Integration Queue semantics

  • Ordering: strict FIFO — at most one integration in flight; a later PR that edits the same file previews against the earlier PR's result.
  • Policy: an item integrates only when its check passed AND preview integration is clean AND (for high-risk work) it is not flagged for approval.
  • Freshness: integration is CAS-guarded; a moved base is re-queued with bounded attempts.
  • Repair loop: preview conflicts block the item and route the attempt to the conflict-resolver; a fix re-queues it.
  • Risk classes: low / medium / high from change scope; risk drives policy escalation.

Security posture

  • Credentials encrypted at rest (AES-256-GCM), metadata-only API, plaintext only at execution resolution. The co-located key protects against database-only compromise, not full host compromise (documented honestly).
  • Repo-scoped short-TTL git tokens; sessions are bcrypt + HttpOnly.
  • Org policies audited end-to-end (allow / deny / escalate with actor + reason).
  • Needs Attention + escalation decision packets let a human decide without reconstructing history.
