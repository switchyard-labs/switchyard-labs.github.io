--- title: Overview ---

Agent-native Git collaboration, built for real.

Switchyard is a self-hosted Git collaboration platform where concurrent autonomous agents and humans work in isolated Git state. Integration into canonical repositories flows through deterministic, policy-controlled serialized integration — not last-writer-wins.

13 checkpoints, end-to-end Real Git hosting on Cloudflare Artifacts Durable programmable workflows Browser editor with draft CAS Real-LLM agent leg pending a provider credential

The core idea

Ordinary Git hosting lets humans push to a branch and merge. Switchyard generalizes that to agents: every actor — human or AI — works on an isolated branch, and the canonical branch only moves through a deterministic, policy-controlled pipeline.

  1. Work — an intent (feature, fix, task) is recorded.
  2. Attempt — an isolated branch is created from the intent.
  3. Agent — an implementer edits files on that branch (deterministic substrate today; a real coding-agent CLI adapter is wired).
  4. Commit — the change lands on the attempt branch via a compare-and-swap ref substrate.
  5. PR + check — a pull request is opened; deterministic validation runs.
  6. Review + preview — findings are produced; preview integration checks whether the branch merges cleanly and whether the merged tree satisfies repo contracts.
  7. Integration Queue — strictly FIFO, policy-gated, CAS-guarded integration into canonical.

Everything is recorded in a durable provenance chain (Work → Attempt → PR → ref updates → events), so every canonical change is attributable.

Why this matters for AI developers

An LLM coding agent editing a shared branch and force-pushing is a liability. Switchyard gives agents:

Isolation

No canonical write access

Agents hold scoped repo tokens for their attempt branch only. Canonical is unreachable by an agent.

Concurrency

No last-writer-wins

Ref mutations are compare-and-swap; stale writers are rejected. Drafts use revision CAS too.

Durability

Durable workflows

JS-authored workflows replay after process death; completed steps are never re-executed.

Governance

Policy + risk

Org policies gate what agents may touch, which integrations need approval, and how much they may run.

Honest status

Proven end-to-end: the deterministic loop — Work → Attempt → agent → edit → PR → review → preview → Integration Queue → canonical — runs against a repository seeded with Switchyard's own source.
Bounded: the real LLM coding-agent leg (CLI adapter) is implemented and wired but not yet exercised, because no provider credential and no coding-agent CLI exist on the control-plane host. The deterministic adapter runs on the identical substrate.
