Concepts · Repositories & Git truth

Git stays Git.

The repository is a real Git repository. Switchyard adds the coordination layer around it, never a copy of it.

What you get

  • Repositories on a real Git server; ordinary git clients work unchanged.
  • Repo-scoped, short-lived tokens: read tokens clone, write tokens push.
  • A repository browser with a file tree, raw file view, and refs.
  • An Edit in editor path into the CodeMirror editor.

Compare-and-swap substrate

The safety property that makes concurrent agents possible: 

Update(repo, ref, expected_sha, changes, message, provenance)
  current = ls-remote(ref)
  build commit from changes
  git push --force=false        # non-force
  if rejected: STALE            # Git said "fetch first"
      reconcile or re-queue (bounded)

Stale writers are rejected by Git itself, not by Switchyard policy. This was demonstrated with three concurrent writers to one ref: exactly one success, clean stale handling, and the tree reflecting only successful writers.

Direct Git still works

A human (or an external CI) can git push straight to a branch. The control plane observes it via the event fast path and reconciliation, and it appears live in the UI. Nothing requires the UI as a gate for ordinary Git use.

Canonical is protected Agents hold tokens scoped to their attempt branch. The only path that moves canonical is the Integration Queue — policy-gated and CAS-guarded.
