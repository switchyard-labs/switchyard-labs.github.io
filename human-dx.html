Human developer experience

Switchyard must feel like excellent ordinary Git hosting — and add the surfaces a human needs to supervise autonomous agents.

Ordinary Git, unchanged

  • Repositories live on a real Git server; git clone / pull / push work out of the box with repo-scoped tokens.
  • An external git push to a branch is observed (fast path + reconciliation) and appears live in the UI via SSE.
  • Your branch history, diffs, and merges are the real git history.

Browser editor

  • CodeMirror 6 with line numbers, history, highlighting, and a dark theme.
  • Save ≠ Commit. Saving writes a durable draft that survives reload; only an explicit Commit changes the repository (through the shared ref substrate).
  • No last-writer-wins. Drafts use revision compare-and-swap: a stale save is rejected with draft_stale and the editor reloads the current revision instead of overwriting it. If the branch moved after your draft was based, Commit reports stale_base with guidance rather than silently rebasing your work.
  • Diff surface shows your draft versus the committed content.
  • Findings panel lists file-scoped review findings.
  • Agent panel runs the implementer against the attempt branch (formal Attempt mode) and refreshes committed state.
Honest gap: the interactive draft-assistance flow — you ask the Agent to edit your draft, it proposes a change, you inspect the diff, then you choose Commit — is not yet implemented. Today the Agent panel uses the formal Attempt path (legitimate autonomous commits). Draft CAS is the correct substrate for the interactive flow and is a CP14/v1 target.

Needs Attention

/api/attention aggregates everything that needs a decision: attempts parked in conflict, blocked queue items, workflow runs waiting for approval, and open error findings. One endpoint, one list, no archaeology.

Escalation decision packets

When a change is blocked, you can escalate it into a self-contained decision packet: target, repository, branch, base, the conflicting files with base + source versions, the findings, and suggested resolutions. You decide without reconstructing history:

DecisionWhat happens
take_oursCanonical's version wins; the attempt is resolved and can be re-queued.
take_theirsThe attempt's version is kept (recorded; note this alone doesn't resolve a real content conflict).
three_wayA real three-way merge (git merge-file) resolves the files.
approveUnblocks a workflow waiting for approval.
requeueRe-runs a blocked integration item.

Organisation & policy (v1)

  • Orgs own repos; members and owners are recorded.
  • Policies are evaluated at run choke points: which files the implementer may write, which integration risk requires approval, workflow step budgets.
  • Every decision is audited (allow / deny / escalate + actor + reason).
  • A fleet view aggregates repos, queue items, workflow runs, and escalations per org.
This proves the organisation/policy architecture. Enterprise authorization (role enforcement matrices, SSO, org-secret lifecycle, compliance retention) is later hardening, not claimed here.

Mobile & accessibility

  • Dark-first shell with a full-screen hamburger menu (a hidden-menu CSS bug was found and fixed by the browser test gate).
  • Responsive layouts; keyboard/focus accessibility and a full browser matrix are CP14 UX items.
