The stack, and why each piece exists

Every component was chosen to preserve two truths: Git is the truth (ordinary git clients work unchanged) and coordination is durable (nothing important lives only in a process or a browser tab).

Core components

LayerTechnologyRole in Switchyard
Git truth Cloudflare Artifacts A real Git server. Repositories live here; ordinary git clone / push / pull work out of the box. Objects/refs/commits are exactly what git wrote. This is why "switch to a different Git host" is never needed.
Coordination truth Trestle (single-node) A record store with idempotent writes and If-Match compare-and-swap. Work, attempts, PRs, findings, queue items, workflow runs, escalations, audit — all durable coordination state.
Bounded execution Strut + a deterministic worker Agent work runs inside a bounded executor. A deterministic worker proves the substrate (fixed input → fixed edit); a real coding-agent CLI adapter is wired behind the same runner interface.
Control plane Go, single binary One self-hosted process: HTTP API, ref substrate, reconciliation, event consumer, workflow runner, integration queue, policy engine, SSE. No framework lock-in.
Web UI Nift-built static + CodeMirror 6 Dark, mobile-friendly app shell; a real browser editor (line numbers, history, diff panel, findings, Agent panel). Built to static assets so it can be hosted anywhere.

Why these choices

Git truth

Artifacts, not a custom store

Git's object model already solves history, diffing, and merge. Store the objects there; treat the repo as authoritative. CAS falls out of non-force push semantics.

Durable coordination

Records, not memory

Every decision, run, finding, and integration is a record. Restart the control plane and nothing important is lost.

Bounded agents

Adapter, not a fork

One runner interface; the deterministic adapter proves the contract; a coding-agent CLI adapter slots in without redesigning the substrate.

Self-hosted

One binary, documented env vars

Point it at a Trestle, an Artifacts namespace, a token helper, and a worker; it runs. No Kubernetes required.

The dual-path event architecture

External Git movement is observed twice, by design:

Fast path

git push → cf.artifacts.repo.pushed → Cloudflare Queue → Switchyard consumer → normalized event → Trestle → SSE

Responsive. The consumer pulls, ingests through the same idempotent path, and acks.

Safety net

periodic git reconciliation → normalized event → Trestle → SSE

Correct. Repairs anything missed while the control plane was down or the queue lagged.

Both paths share the transition identity (repo, ref, before, after), so the same Git movement observed by both converges to one durable domain event and one broadcast. Events accelerate convergence; reconciliation guarantees it.
Upstream note: Cloudflare's event-subscription → Queue delivery for cf.artifacts.repo.pushed was proven in CP0 but is currently not flowing account-wide. The Switchyard fast path is implemented and gated from the Queue onward; reconciliation covers correctness meanwhile.

Interesting details

  • Queue messages are JSON-encoded strings; the consumer decodes the string, then the envelope.
  • Trestle's Idempotency-Key returns replayed=true only for byte-identical content; the same identity with different metadata yields 409 idempotency_conflict — treated as convergence, not an error.
  • Scratch clones are used per mutation (preview, merge, diff, changed-files). Measured ~4 s per integration — a real CP14 optimization target (bare mirror + worktree).
